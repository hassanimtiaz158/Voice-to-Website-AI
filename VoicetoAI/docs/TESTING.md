## 1. Testing Philosophy & Inviolable Rules

The Voice-to-Website AI platform enforces software verification through deterministic tools rather than human opinions.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        CORE TESTING INVARIANTS                         │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Verify with Tools, Not Opinions: Code generated by an LLM is        │
│    considered broken until verified by compiler, linter, and browser.  │
├────────────────────────────────────────────────────────────────────────┤
│ 2. Backward Compatibility Lock: No new phase may break tests from any   │
│    prior phase. The entire regression suite runs on every pull request.│
├────────────────────────────────────────────────────────────────────────┤
│ 3. Balanced Ledger Assertion: Every financial transaction test must    │
│    assert sum(debits) == sum(credits) to the exact cent.               │
└────────────────────────────────────────────────────────────────────────┘
```

| Level | Scope | Primary Framework | Target Coverage | Execution Frequency |
|---|---|---|---|---|
| **Unit** | Pure functions, parsers, models | `pytest`, `vitest` | $\ge 85\%$ line coverage | Pre-commit & CI |
| **Contract** | Inter-agent Pydantic schemas | `pytest contracts/` | $100\%$ schema coverage | Every PR |
| **Integration** | DB, pgvector, MinIO, E2B | `pytest` + Testcontainers | All primary data flows | Every PR |

| **Benchmark** | Quantitative FYP evaluations | Custom Python Harness | 30 scenarios per benchmark| Weekly & Milestones |
| **Load** | Concurrency & latency testing | `Locust` | 50 concurrent active users | Milestone M4 & M5 |

## 3. Playwright Headless Sandbox Verification

Inside the E2B microVM or local Docker sandbox, Playwright executes headless smoke audits before any code can be promoted to `main`.

```typescript
// scaffolds/vite-react-tailwind/tests/smoke.spec.ts
import { test, expect } from '@playwright/test';

test.describe('Automated Sandbox Verification Suite', () => {
  test('Visual & Functional Invariants', async ({ page }) => {
    const errorLogs: string[] = [];
    page.on('console', msg => {
      if (msg.type() === 'error') errorLogs.push(msg.text());
    });
    page.on('pageerror', err => errorLogs.push(err.message));

    // 1. Navigation & Hydration
    const response = await page.goto('http://localhost:4173', { waitUntil: 'networkidle' });
    expect(response?.status()).toBe(200);

    // 2. Zero Uncaught Console Errors
    expect(errorLogs).toEqual([]);

    // 3. Document Title Presence
    await expect(page).toHaveTitle(/^(?!\s*$).+/);

    // 4. Layout Overflow Detection (Zero Horizontal Scrollbar)
    const isOverflowing = await page.evaluate(() => {
      return document.documentElement.scrollWidth > window.innerWidth;
    });
    expect(isOverflowing).toBe(false);

    // 5. Visual Artifact Capture
    await page.screenshot({ path: '/tmp/artifacts/preview.png', fullPage: true });
  });
});
```

## 4. Double-Entry Accounting Ledger Invariant Test

```python
import pytest
from backend.app.services.ledger import execute_ledger_transaction, LedgerImbalanceException

def test_ledger_immutability_and_balance():
    # Attempting to post an unbalanced transaction must throw LedgerImbalanceException
    unbalanced_entries = [
        {"account_type": "user_escrow", "entity_id": "u1", "debit_cents": 5000, "credit_cents": 0},
        {"account_type": "escrow_holding", "entity_id": "sys", "debit_cents": 0, "credit_cents": 4900} # $1 leak
    ]
    
    with pytest.raises(LedgerImbalanceException):
        execute_ledger_transaction(unbalanced_entries)
```

## 5. Quantitative Evaluation Benchmark Harnesses

The platform features an automated benchmark suite in `evals/` to prove model performance empirically:

```python
# evals/run_all_benchmarks.py
from evals.asr_eval import evaluate_asr_wer
from evals.clarifier_eval import evaluate_clarifier_turns
from evals.build_benchmark import evaluate_greenfield_builds
from evals.locator_eval import evaluate_surgical_locator

def run_full_suite():
    print("=== Running FYP Benchmark Evaluation Suite ===")
    
    # 1. ASR Bilingual WER Benchmark (30 clips)
    wer_score = evaluate_asr_wer("evals/audio_clips/")
    assert wer_score <= 0.14, f"ASR WER {wer_score} failed threshold"
    
    # 2. Clarifier Efficiency (20 personas)
    avg_turns = evaluate_clarifier_turns("evals/personas/")
    assert avg_turns <= 3.0, f"Clarifier avg turns {avg_turns} exceeded 3"
    
    # 3. Greenfield Build Benchmark (30 scenarios)
    build_pass_rate = evaluate_greenfield_builds("evals/build_scenarios/")
    assert build_pass_rate >= 0.85, f"Build pass rate {build_pass_rate} below 85%"
    
    # 4. Surgical Edit Accuracy (30 edit tasks)
    locator_accuracy = evaluate_surgical_locator("evals/edit_tasks/")
    assert locator_accuracy >= 0.90, f"Locator accuracy {locator_accuracy} below 90%"
    
    print("ALL ACCEPTANCE BENCHMARKS PASSED SUCCESSFULLY.")

if __name__ == "__main__":
    run_full_suite()
```

## 6. Manual Testing Checklist Before Committee Defense

- [ ] Complete voice input test in noisy room; verify VAD silence triggers modal.
- [ ] Inspect Urdu transcript text; edit one misspelled word in modal and submit.
- [ ] Complete clarification interview; choose "You Decide" on 1 question.
- [ ] Inspect build log console view; verify real-time compiler outputs.
- [ ] Review live website in desktop and mobile preview modes.
- [ ] Issue spoken modification: "Change banner color to royal blue"; verify only `Hero.tsx` or `tailwind.config.js` changes in Git diff.
- [ ] Click "Rollback to v1"; assert preview immediately reverts.
- [ ] Request deployment live; assign developer in Admin window; open workroom chat.
- [ ] Submit quote; pay via mock gateway; verify database `ledger_entries` balance.
